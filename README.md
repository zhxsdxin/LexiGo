# LexiGo

极简日语单词学习网站。零依赖、无构建步骤，双击 `index.html` 即可使用。

## 运行方式

**方式一：直接打开（最简单）**

双击 `index.html`，或拖进浏览器窗口。所有功能均可用，学习记录保存在浏览器本地。

**方式二：本地静态服务器（推荐用于手机测试）**

```bash
cd LexiGo
python3 -m http.server 8848
```

然后访问 `http://127.0.0.1:8848`。手机与电脑在同一 WiFi 下时，把 `127.0.0.1` 换成电脑的局域网 IP 即可在手机上访问。

浏览器要求：Chrome / Safari / Edge / Firefox 的近两年版本。

## 使用说明

### 学习（默认首页）

卡片可以左右翻转，两个面分别是：

- **正面** — 日语单词 + 音调
- **背面** — 读音假名 + 词性 + 中文释义（词库中有例句时一并显示）

翻转用 CSS 3D Transform 实现：整张卡（连同卡面底色、描边、阴影与发音按钮）沿 Y 轴旋转 180°，动画 350ms `ease-in-out`，透视距离 1000px。正反两面各自 `backface-visibility: hidden`，同一时刻只可见一面，过程中无残影、无闪烁。切换单词时卡片自动回正到正面。

**「认识 / 不认识」常驻在卡片下方，不需要先翻面。**

1. 先在心里回忆这个单词的意思。
2. 三种操作：
   - **认识** → 直接跳到下一个词，熟练度升级，下次复习间隔自动拉长。
   - **不认识** → 卡片翻到背面展示答案，同时该词进入错词复习队列。
   - **点击卡片 / 空格** → 手动翻面看答案，或从背面翻回正面。
3. 底部可切换上一词 / 下一词，右下角图标切换随机顺序。
4. 底部计数器本身就是词表入口，点击展开本组全部单词，点条目直接跳转。

**词表检索**：展开后的词表顶部有搜索框，打开即聚焦。可按**中文释义**、**词目**、**假名**、**源语言**、**罗马字**五种方式检索：

| 输入 | 命中 |
| --- | --- |
| `味道` / `运动` | 按中文释义（释义已在索引内） |
| `味` / `あじ` | 按词目 / 假名 |
| `guide` / `Energie` | 按外来语源语言 |
| `aji` / `kazoku` | 按罗马字（Hepburn） |
| `jisin` / `zisin` | 按罗马字（训令式） |

罗马字由 `assets/js/core/romaji.js` 从假名实时转换，同时索引 Hepburn 与训令式两套写法，促音（きって → `kitte` / `kite`）、拨音（しんぶん → `shimbun`）、长音（コーヒー → `kohi`）都做了处理；检索时忽略空格、连字符与撇号，`shi-bun`、`kan'i` 这类写法也能命中。无匹配时显示提示，关闭搜索框自动清空。

**触屏手势**（移动端）

| 手势 | 作用 |
| --- | --- |
| 左右滑动 | 切换上一个 / 下一个单词 |
| 上下滑动 | 翻转卡片 |
| 轻点 | 翻转卡片 |

滑动阈值 48px，小幅移动不会误触发；滑动不会产生作答记录，也不影响发音按钮和词表选择框。

**快捷键**：`空格` 翻转卡片 · `←` `→` 切换词 · `R` 发音 · `1` `2` `3` 切换标签页 · `?` 操作说明

顶栏右侧的问号按钮（或按 `?`）可以随时打开操作说明，键盘、触屏、作答三类说明都在里面，不占用单词卡片的空间。

### 复习

自动收集学习时标记为「不认识」的词，按熟练度从低到高排队。卡片翻转与按钮逻辑与学习页一致。

- **认识** → 从本轮队列移出，间隔按 10 分钟 → 1 天 → 3 天 → 7 天逐级拉长。
- **不认识** → 打回最基础等级，本轮内隔 2 个词再考一次，同时翻面展示答案。
- 底部计数器展开可看到本轮全部待复习词及其熟练度，点条目直接跳转。
- 没有到期的错词时显示完成状态，点「重新开始一轮」可召回所有未掌握的词。

### 进度

- 今日已学习词数、认识 / 不认识分布与命中率
- 词库整体学习进度
- 掌握程度分布（未掌握 → 牢固 五档）
- 待复习错词数量与需要多看几眼的词清单

底部「清空学习记录」需点击两次确认。

## 词库与子集

顶栏的书本图标打开选择器，可以切换词库、勾选子集。支持**单选**（只练一类）和**多选**（合并练习）。

### 内置词库

| 词库 | 词数 | 说明 |
| --- | --- | --- |
| 示例词库 | 5 | 最初手工整理的示例，快速体验交互 |
| N3 词汇王炸 | 1483 | 从 PDF 词单 OCR 提取的完整词库 |
| N2 词汇王炸 | 1482 | 从 PDF 词单 OCR 提取的完整词库 |

### 子集划分

子集定义是**按词库无关的 `part` / `chapter` 字段匹配**的，两套词库共用同一组子集，只是词数不同：

| 子集 | N3 | N2 |
| --- | --- | --- |
| 基础词 | 364（`n3b1`–`n3b364`） | 389（`n2b1`–`n2b389`） |
| 汉字 | 495（`n3ch1`–`n3ch495`） | 441（`n2ch1`–`n2ch441`） |
| 动词 | 268（`n3cd1`–`n3cd268`） | 297（`n2cd1`–`n2cd297`） |
| 形容词 | 140（`n3cx1`–`n3cx140`） | 175（`n2cx1`–`n2cx175`） |
| 外来语 | 114（`n3cw1`–`n3cw114`） | 130（`n2cw1`–`n2cw130`） |
| 副词 | 102（`n3cf1`–`n3cf102`） | 50（`n2cf1`–`n2cf50`） |

六个分篇覆盖全部核心词，互不重叠。ID 规则是 `n3` / `n2` + 分篇前缀 + 分篇内序号，**序号与词单 PDF 里的序号一一对应**（如 `n3b364` 就是基础词最后一词「割り勘」，`n2b389` 是「苦労を重ねる」）。勾选结果存在 `localStorage`（按词库分别记录），刷新后保持；清空子集会显示引导空状态，点一下即可回到选择器。

进度统计、复习队列、词表跳转全部跟随当前范围，只针对选中的子集。

### 从 PDF 重新提取词库

`tools/extract_words.py` 负责把词单 PDF 转成词库 JS，N3 / N2 共用同一套脚本，靠参数区分身份：

```bash
python3 tools/extract_words.py \
  --pdf "<词单.pdf>" \
  --out assets/js/data/n2-words.js \
  --dump tools/n2-raw.json \
  --bank-id n2 --bank-name "N2词汇王炸" --global N2_BANK \
  --source "【N2-Plus-词汇补弱】N2词汇王炸套餐背词版（极速版词单）" \
  --chapter-order "汉字,动词,形容词,外来语,副词"
```

PDF 是纯图片扫描件，没有文字层，所以流程是：渲染页面 → 从位图找出表格线还原单元格网格 → 逐格 OCR → 组装词条。

依赖 `pymupdf`、`numpy`，以及 macOS 自带的 Vision 框架（`tools/vision_ocr_cells.swift`，首次运行会自动编译成二进制）。

关键实现：

- **表格网格还原**：分隔线的强度要相对**表格的纵向范围**算，而不是整页。表格占满整页时实线强度约 0.93，短表格（如只有 22 行、占页高 42% 的那几页）整页强度会被稀释到 0.42，用整页阈值会把这些页面整页漏掉。换成表内强度后两种页面都是 1.00，文字笔画只有 0.33。横线数量下限取 3 条（2 个行带）——N2 形容詞篇末页只剩 2 行数据且无表头，整页只有 3 条横线，用 4 条会把这两行丢掉。
- **单元格裁剪**：只取单元格内部并自动裁到墨迹边界，去掉表格边框线。带边框的单字裁剪图识别结果为空（豆、草、石 等都会丢），去边框后同一个字能正常读出。
- **表头与标题行识别**：靠结构而非行号。表头行要求单词/读音/词性/释义四列里有 ≥2 列命中噪声词表——单列匹配会误伤真词（实测 #388「単語」的释义列被读成「単司」）；分篇标题行（红色大字）在表头行的紧上方，按位置剔除。
- **声调识别**：OCR 对 ⓪ ①②③④ 这类空心圈字符不稳定（漏识或读成 `o`/`4`）。先用 `tools/pitch_match.py` 的模板匹配兜底，模板从本页 OCR 成功的样本自校准得到。带圈数字按 Unicode 区段通用解码到 ⑳ 以上，长词音调（⑤、⑥）也能识别。
- **词性归一化**：词单原文是「名 / 形 / 副 / 動1 / サ変」这类简写，OCR 会把 `動` 认成「劫/劯/功/効」、`サ変` 认成「砂3/あ3」。先做字符级纠错再归一化成中文词性。动词的语态前缀（自動/他動/自他動）被读成「自云/他方/自代」等变体时，按「以自/他 开头即动词」兜底。
- **篇名识别**：两套词单版式不同，都要兼容。N3 每页页眉都带「基础词篇 / 核心词篇」；N2 的篇名只在分隔页出现，表格页页眉没有，因此非词表页要整页 OCR 认篇名。分篇标题只在每章首页顶部，N2 的外来词/副词首页标题常被读成「外来司」「副司」，此时用「该页序号回到 1」判定换章，按 `--chapter-order` 给的固定顺序推进。
- **繁简统一**：释义列的繁体字统一转简体。

词条字段：

```js
{
  id: 'n2b1',         // n2 + 分篇前缀 + 分篇内序号，对应 PDF 序号
  word: '暗算',        // 日语表记字
  kana: 'あんざん',    // 读音假名
  pitch: 0,           // 音调 0-N，null 表示词单未标
  pos: '动词',         // 主词性
  posAll: '名词|动词', // 全部词性，用 | 分隔
  meaning: '心算',     // 中文释义
  src: 'almond',      // 外来语的源语言写法（仅外来语有，如 アーモンド → almond）
  part: 'basic',      // basic | core
  chapter: ''         // 汉字 / 动词 / 形容词 / 外来语 / 副词（核心词篇用）
}
```

`src` 的来由：两套词单的「读音」列对外来语填的都是英文原词（`イベント / event`），这是词单原样如此。提取时把它单独放进 `src`，读音还原成片假名；界面上普通模式背面、假名模式正面会显示这个源语言词。

音调显示字符在 `assets/js/data/banks.js` 的 `PITCH_MARK` 里用 Unicode 转义写死：带圈零 ⓪ 是 `U+24EA`，而 1–4 必须用 `U+2460–U+2463`。看似对应的 `U+24EB–24EE`（⓫⓬⓭⓮）在 Unicode 里其实是「黑圈拉丁小写字母 b/c/d/e」，字体渲染成黑底白字，显示全错。当前支持到 ⑪，两套词库的音调最大值都是 ⑤。

### 已知的数据限制

词单是扫描件，OCR 无法达到人工录入的精度：

- 中文释义里的字存在系统性错认（N3 已逐条严查重译 760 余条；N2 尚未做，如「競う=竟争、比賽」「緊迫=紫迫」）。这类错误无法用映射表穷举，需要人工校对。可编辑 `tools/n*-raw.json` 后重新生成 JS。
- N2 有 426 条词没有音调（`pitch:null`，占 28.7%），界面不显示音调符号。可接 Wadoku 声调词典按读音回填（N3 已用同一办法补齐）。
- N3 有 1 条（汉字篇，假名「けつあつ」）单词列为空，需人工补录。可直接编辑 `tools/n3-raw.json` 后重新生成 JS。

## 数据存储

学习记录保存在浏览器 `localStorage` 的 `lexigo.state.v1` 键下，不上传服务器，换设备不同步。

- 只保留最近 30 天的每日统计，避免存储无限增长。
- 浏览器禁用存储（隐私模式）时自动降级为内存态，页面功能不受影响，进度页会提示记录不会保留。
- 本地数据损坏或版本升级缺字段时会自动重置为初始状态，不会导致页面白屏。
