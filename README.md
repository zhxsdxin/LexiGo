# LexiGo

极简日语单词学习网站。零依赖、无构建步骤，双击 `index.html` 即可使用。

## 运行方式

**方式一：直接打开（最简单）**

双击 `index.html`，或拖进浏览器窗口。所有功能均可用，学习记录保存在浏览器本地。

**方式二：本地静态服务器（推荐用于手机测试）**

```bash
cd LexiGo
python3 -m http.server 8848
```

然后访问 `http://127.0.0.1:8848`。手机与电脑在同一 WiFi 下时，把 `127.0.0.1` 换成电脑的局域网 IP 即可在手机上访问。

浏览器要求：Chrome / Safari / Edge / Firefox 的近两年版本。

## 使用说明

### 学习（默认首页）

卡片可以左右翻转，两个面分别是：

- **正面** — 日语单词 + 音调
- **背面** — 读音假名 + 词性 + 中文释义（词库中有例句时一并显示）

翻转用 CSS 3D Transform 实现：整张卡（连同卡面底色、描边、阴影与发音按钮）沿 Y 轴旋转 180°，动画 350ms `ease-in-out`，透视距离 1000px。正反两面各自 `backface-visibility: hidden`，同一时刻只可见一面，过程中无残影、无闪烁。切换单词时卡片自动回正到正面。

**「认识 / 不认识」常驻在卡片下方，不需要先翻面。**

1. 先在心里回忆这个单词的意思。
2. 三种操作：
   - **认识** → 直接跳到下一个词，熟练度升级，下次复习间隔自动拉长。
   - **不认识** → 卡片翻到背面展示答案，同时该词进入错词复习队列。
   - **点击卡片 / 空格** → 手动翻面看答案，或从背面翻回正面。
3. 底部可切换上一词 / 下一词，右下角图标切换随机顺序。
4. 底部计数器本身就是词表入口，点击展开本组全部单词，点条目直接跳转。

**触屏手势**（移动端）

| 手势 | 作用 |
| --- | --- |
| 左右滑动 | 切换上一个 / 下一个单词 |
| 上下滑动 | 翻转卡片 |
| 轻点 | 翻转卡片 |

滑动阈值 48px，小幅移动不会误触发；滑动不会产生作答记录，也不影响发音按钮和词表选择框。

**快捷键**：`空格` 翻转卡片 · `←` `→` 切换词 · `R` 发音 · `1` `2` `3` 切换标签页 · `?` 操作说明

顶栏右侧的问号按钮（或按 `?`）可以随时打开操作说明，键盘、触屏、作答三类说明都在里面，不占用单词卡片的空间。

### 复习

自动收集学习时标记为「不认识」的词，按熟练度从低到高排队。卡片翻转与按钮逻辑与学习页一致。

- **认识** → 从本轮队列移出，间隔按 10 分钟 → 1 天 → 3 天 → 7 天逐级拉长。
- **不认识** → 打回最基础等级，本轮内隔 2 个词再考一次，同时翻面展示答案。
- 底部计数器展开可看到本轮全部待复习词及其熟练度，点条目直接跳转。
- 没有到期的错词时显示完成状态，点「重新开始一轮」可召回所有未掌握的词。

### 进度

- 今日已学习词数、认识 / 不认识分布与命中率
- 词库整体学习进度
- 掌握程度分布（未掌握 → 牢固 五档）
- 待复习错词数量与需要多看几眼的词清单

底部「清空学习记录」需点击两次确认。

### 从 PDF 重新提取词库

`tools/extract_words.py` 负责把词单 PDF 转成 `assets/js/data/n3-words.js`：

```bash
python3 tools/extract_words.py \
  --pdf "<词单.pdf>" \
  --out assets/js/data/n3-words.js \
  --dump tools/n3-raw.json
```

PDF 是纯图片扫描件，没有文字层，所以流程是：渲染页面 → 从位图找出表格线还原单元格网格 → 逐格 OCR → 组装词条。

依赖 `pymupdf`、`numpy`，以及 macOS 自带的 Vision 框架（`tools/vision_ocr_cells.swift`，首次运行会自动编译成二进制）。

关键实现：

- **表格网格还原**：分隔线的强度要相对**表格的纵向范围**算，而不是整页。表格占满整页时实线强度约 0.93，短表格（如只有 22 行、占页高 42% 的那几页）整页强度会被稀释到 0.42，用整页阈值会把这些页面整页漏掉。换成表内强度后两种页面都是 1.00，文字笔画只有 0.33。
- **单元格裁剪**：只取单元格内部并自动裁到墨迹边界，去掉表格边框线。带边框的单字裁剪图识别结果为空（豆、草、石 等都会丢），去边框后同一个字能正常读出。
- **表头与标题行识别**：靠结构而非行号。表头行要求单词/读音/词性/释义四列里有 ≥2 列命中噪声词表——单列匹配会误伤真词（实测 #388「単語」的释义列被读成「単司」）；分篇标题行（红色大字）在表头行的紧上方，按位置剔除。
- **声调识别**：OCR 对 ⓪ ①②③④ 这类空心圈字符不稳定（漏识或读成 `o`/`4`）。先用 `tools/pitch_match.py` 的模板匹配兜底，模板从本页 OCR 成功的样本自校准得到。补齐率约 88%，剩余 64 条标记为 `pitch: null`，界面不显示音调。
- **词性归一化**：词单原文是「名 / 形 / 副 / 動1 / サ変」这类简写，OCR 会把 `動` 认成「劫/劯/功/効」、`サ変` 认成「砂3/あ3」。先做字符级纠错再归一化成中文词性。
- **篇名识别**：页面左上角是「基础词篇 / 核心词篇」，其下是红色分篇标题，同样会被 OCR 认成形近字（「基砧河篇」「汊字」「外来洞」等），已把实际出现的变体列进匹配表。
- **繁简统一**：释义列的繁体字统一转简体。

词条字段：

```js
{
  id: 'n3b1',         // n3 + 分篇前缀 + 分篇内序号，对应 PDF 序号
  word: '味',          // 日语表记字
  kana: 'あじ',        // 读音假名
  pitch: 0,           // 音调 0-4，null 表示词单未标
  pos: '名词',         // 主词性
  posAll: '名词',      // 全部词性，用 | 分隔
  meaning: '味道',     // 中文释义
  part: 'basic',      // basic | core
  chapter: ''         // 汉字 / 动词 / 形容词 / 外来语 / 副词（核心词篇用）
}
```

音调显示字符在 `assets/js/data/banks.js` 的 `PITCH_MARK` 里用 Unicode 转义写死：带圈零 ⓪ 是 `U+24EA`，而 1–4 必须用 `U+2460–U+2463`。看似对应的 `U+24EB–24EE`（⓫⓬⓭⓮）在 Unicode 里其实是「黑圈拉丁小写字母 b/c/d/e」，字体渲染成黑底白字，显示全错。

### 已知的数据限制

词单是扫描件，OCR 无法达到人工录入的精度：

- 少量中文释义里的字被认成形近字（如「活动」读成「活砂」）。这类错误无法用映射表穷举，需要人工校对。可编辑 `tools/n3-raw.json` 后重新生成 JS。
- 约 80 条词没有音调（`pitch: null`），界面不显示音调符号。
- 有 1 条（汉字篇，假名「けつあつ」）单词列为空，需人工补录。可直接编辑 `tools/n3-raw.json` 后重新生成 JS。
- 外来词在词单里的读音列填的是英文原词（如 `イベント / event`），这是词单原样如此，已保留。

## 数据存储

学习记录保存在浏览器 `localStorage` 的 `lexigo.state.v1` 键下，不上传服务器，换设备不同步。

- 只保留最近 30 天的每日统计，避免存储无限增长。
- 浏览器禁用存储（隐私模式）时自动降级为内存态，页面功能不受影响，进度页会提示记录不会保留。
- 本地数据损坏或版本升级缺字段时会自动重置为初始状态，不会导致页面白屏。
